## 1. Общая архитектура

Проект представляет собой Action RPG / Souls-like игру от третьего лица. Основные механики реализованы через компонентную систему Unity с использованием:
- **PlayerPrefs** для локального сохранения прогресса
- **DontDestroyOnLoad** синглтонов для персистентных систем (PlayerStats)
- **Event-driven** подход (Action/Func делегаты) для связи между системами
- **State Machine** для контроллера игрока (все состояния в одном файле PlayerController.cs)

## 2. Система валюты и прокачки (Currency & Level-Up)

### 2.1 PlayerStats.cs — ядро системы

**Роль:** DontDestroyOnLoad синглтон. Создаётся в сцене MainMenu. Хранит и управляет всеми характеристиками игрока.

**Ключевые поля:**
- `baseStatLevel = 8` — стартовый уровень каждого из 6 статов
- `baseCurrencyCost = 100` — базовая стоимость прокачки
- `soulLevelCostRate = 0.08f` — наценка 8% за каждый уровень души выше 48
- `statLevelCostRate = 0.03f` — наценка 3% за каждый уровень стата выше 8
- `startingCurrency = 0` — стартовое количество душ

**Формула стоимости:**
```
cost = baseCost × (1 + 0.08 × (SoulLevel - 48)) × (1 + 0.03 × (statLevel - 8))
```

**6 статов (StatType enum):**
| Индекс | Название | Эффект за уровень выше 8 |
|--------|----------|--------------------------|
| 0 | Strength (Сила) | +2 к урону оружия |
| 1 | Dexterity (Ловкость) | +10 к макс. стамине |
| 2 | Vitality (Здоровье) | +10 к макс. HP (и восстановление разницы) |
| 3 | Resistance (Сопротивление) | Пока не влияет |
| 4 | Defense (Защита) | -1 к входящему урону |
| 5 | Luck (Удача) | +10 к получаемым душам |

**Важные методы:**
- `AddCurrency(int amount)` — добавляет души + бонус удачи. Вызывает `OnCurrencyChanged` и `SaveStats()`
- `LevelUpStat(StatType)` — снимает валюту, повышает стат, вызывает `ApplyStatBonuses()`, сохраняет в PlayerPrefs
- `ApplyStatBonuses()` — применяет бонусы к Health.SetMaxHealth() и Stamina.SetMaxStamina()
- `SubscribePlayerDefense()` — подписывает `ApplyDefense()` на `Health.OnModifyIncomingDamage`
- `ResetAllToDefault()` — сброс к стартовым значениям (вызывается по F9 через PlayerController)
- `GetLevelUpCost(StatType)` — рассчитывает стоимость следующего уровня

**Сохранение (PlayerPrefs):**
- `PS_Currency` — текущие души
- `PS_Stat_0` … `PS_Stat_5` — уровни статов
- `PS_` префикс используется для избежания конфликтов с другими сохранениями

**События:**
- `OnCurrencyChanged(int)` — вызывается при изменении валюты
- `OnStatsChanged` — вызывается при прокачке статов

### 2.2 CurrencyUI.cs — счётчик душ

**Роль:** Отображает текущее количество душ в правом верхнем углу экрана.

**Особенности реализации:**
- Создаёт свой `Canvas` с `DontDestroyOnLoad` при первом запуске
- Использует **polling** (каждый кадр проверяет `PlayerStats.Instance.Currency`) вместо подписки на события — это надёжнее при смене сцен
- Плавная анимация чисел: `countSpeed = 200` — скорость изменения отображаемого числа к целевому
- `Time.unscaledDeltaTime` — работает даже при `Time.timeScale = 0`
- Полупрозрачный тёмный фон (`Image.color = new Color(0,0,0,0.5f)`)
- Светло-оранжевый текст (`Color(1f, 0.85f, 0.3f)`)

**Автосоздание UI:**
- Canvas (ScreenSpaceOverlay, sortingOrder=50)
- Panel (anchorMin/Max = (1,1), pivot=(1,1), anchoredPosition=(-20,-20))
- TextMeshProUGUI (alignment=Right, fontSize=28, Bold)

### 2.3 LevelUpMenu.cs — меню прокачки

**Роль:** Полноценное меню прокачки со всей логикой планирования и подтверждения.

**Архитектура:**
- Компонент добавляется на `Panel` в сцене (или создаётся автоматически LevelUpShrine)
- Управляется через `CanvasGroup` (alpha/interactable/blocksRaycasts)
- Все UI-элементы создаются программно в методе `Build()` при первом открытии
- Сохраняет ссылки на созданные элементы в массивах

**Интерфейс (6 строк статов + заголовки + кнопки):**
- **Заголовок:** `Soul Level: X` (текущий уровень души)
- **Валюта:** `Souls: X` (текущие души)
- **Строка стата (x6):**
  - Название (слева, белый) — из `PlayerStats.StatNames`
  - Описание бонуса (под названием, серый) — из `PlayerStats.StatDescriptions`
  - Текущий уровень (центр) — `8`
  - `→ 9` жёлтым при планировании прокачки
  - `◀` / `▶` кнопки (серые, 30x30)
  - Стоимость (справа, оранжевый) — цена за этот конкретный уровень
- **Итого:** `Total: X souls` (суммарная стоимость всех запланированных прокачек)
- **Кнопки:** `Confirm` (подтвердить), `Reset` (сброс планирования), `Close` (закрыть)

**Логика планирования:**
- `saved[]` — уровни статов на момент открытия меню
- `planned[]` — запланированные уровни (изначально = saved)
- При нажатии `▶`: `planned[i]++` (но не выше 99)
- При нажатии `◀`: `planned[i]--` (но не ниже saved[i])
- Кнопка `Confirm` активна только если `totalCost > 0 && currency >= totalCost`

**При подтверждении:**
```csharp
for each stat:
    while (current < planned):
        PlayerStats.LevelUpStat(type) // снимает деньги, применяет бонусы
        current++
Refresh() // обновляет отображение
```

**При закрытии:**
- `RestoreGame()` — `Time.timeScale = 1`, включает PlayerController, блокирует курсор
- `CanvasGroup.alpha = 0`, `interactable = false` (Panel остаётся активным в сцене)

**Защита от конфликта с ESC:**
- `LevelUpMenu.JustClosed` — флаг на 1 кадр после закрытия
- `GameManager` и `GameMenu` проверяют этот флаг в своём Update
- Предотвращает открытие меню паузы при закрытии меню прокачки по Escape

### 2.4 LevelUpShrine.cs — алтарь прокачки

**Роль:** Триггер взаимодействия в мире. Открывает меню прокачки при нажатии E.

**Настройки в Inspector:**
- `interactionRadius = 3f` — радиус срабатывания
- `interactKey = E` — клавиша взаимодействия
- `promptMessage` — текст подсказки
- `levelUpPanel` — **ссылка на Panel в сцене** (необязательно)
- `promptPanel` — ссылка на UI панель подсказки (необязательно)

**Поведение:**
1. Игрок входит в радиус → показывается подсказка (создаётся автоматически если не назначена)
2. Нажатие E → `HidePrompt()` → `LevelUpMenu.Show()` (или создаёт меню автоматически)
3. Меню открыто → повторное нажатие E или Escape → `LevelUpMenu.Hide()`

**Важно:** Если назначен `levelUpPanel`, Shrine просто активирует его и вызывает `menu.Open()`. Если не назначен — создаёт полный Canvas + Panel + LevelUpMenu программно.

### 2.5 CurrencyDrop.cs — дроп душ с врагов

**Роль:** Навешивается на префабы врагов (требует компонент Health).

**Логика:**
- Подписывается на `health.OnDeath`
- При смерти: `PlayerStats.Instance.AddCurrency(soulValue)`
- `soulValue = 50` (по умолчанию)

## 3. Система стамины (Stamina)

### 3.1 Stamina.cs

**Роль:** Компонент на игроке. Управляет расходом и восстановлением стамины.

**Параметры:**
- `maxStamina = 100` — максимальная стамина
- `regenRate = 30` — скорость восстановления (в секунду)
- `regenDelay = 0.5f` — задержка перед началом восстановления после траты
- `runDrainRate = 15` — расход при беге (в секунду)
- `attackCost = 20` — стоимость атаки
- `rollCost = 15` — стоимость переката
- `jumpCost = 10` — стоимость прыжка

**Методы:**
- `TryUseStamina(float amount)` — пытается потратить. Возвращает `true/false`. Сбрасывает `timeSinceLastUse`
- `DrainContinuous(float rate)` — трата за кадр (для бега). Сбрасывает `timeSinceLastUse`
- `SetMaxStamina(float newMax)` — изменяет максимум. При увеличении восполняет разницу (бесплатное лечение при прокачке)

**Событие:** `OnStaminaChanged(float current, float max)` — вызывается при любом изменении

### 3.2 StaminaUI.cs

**Роль:** Полоска стамины (Filled Image, зелёный цвет).

**Особенности:**
- Lazy-connect — каждый кадр пытается найти `Stamina` через `FindFirstObjectByType`
- Подписывается на `OnStaminaChanged` при нахождении
- Использует `Image.fillAmount` (Filled Image тип)

### 3.3 Интеграция с PlayerController

**Блокировки при недостатке стамины:**
- **Бег:** если `TryUseStamina(runDrainRate * deltaTime)` возвращает false → переход на шаг
- **Блокировка бега:** после полного истощения (0 стамины) бег блокируется на 1 секунду (`exhaustionTimer`) — предотвращает мерцание шаг↔бег
- **Атака:** `HasStamina(attackCost)` — не начинает анимацию если мало стамины
- **Перекат:** `HasStamina(rollCost)` — не начинает анимацию
- **Прыжок:** `HasStamina(jumpCost)` — не начинает анимацию

## 4. Система здоровья и урона

### 4.1 Health.cs

**Роль:** Компонент здоровья для игрока и врагов.

**Ключевые изменения:**
- `baseMaxHealth` — базовый максимум (не меняется)
- `maxHealth` — текущий максимум (может увеличиваться от прокачки)
- `SetMaxHealth(float newMax)` — изменяет максимум. При увеличении восполняет разницу (HP полностью восстанавливается при прокачке Vitality — это задумано)
- `OnModifyIncomingDamage` — `Func<float, float>` позволяет модифицировать входящий урон. PlayerStats подписывает `ApplyDefense()` который вычитает DefenseBonus

**Методы:**
- `TakeDamage(float damage)` — применяет `OnModifyIncomingDamage`, уменьшает HP, вызывает события
- `Heal(float amount)` — лечение с капом в maxHealth
- `FullHeal()` — полное восстановление
- `ResetHealth()` — воскрешение (isDead = false, HP = max)

### 4.2 Weapon.cs

**Роль:** Урон оружия. Управляется через Animation Events.

**Ключевые изменения:**
- `damage = base + PlayerStats.Instance.DamageBonus` (Strength)
- `EnableHitbox()` / `DisableHitbox()` — вызываются из анимации
- `hasHitThisAttack` — защита от множественных попаданий за одну атаку
- `OnTriggerEnter` — наносит урон врагам с тегом "Enemy"

**Интеграция со статами:**
```csharp
float totalDamage = damage + PlayerStats.Instance.DamageBonus;
```

### 4.3 HealthUI.cs

**Роль:** Полоска здоровья (Filled Image, красный).
- Lazy-connect к Health компоненту игрока
- Подписывается на `OnHealthChanged`

## 6. Босс-арена (BossArena)

### 6.1 BossArena.cs

**Роль:** Управляет стенами арены босса.

**Ключевое архитектурное решение:**
- Стены управляются через **`Collider.enabled`** вместо `SetActive(true/false)`
- Это позволяет:
  1. Не блокировать вход в арену до срабатывания триггера
  2. Сохранять видимость стен (они просто становятся нематериальными)
  3. Избежать проблем с расчётом навигации (NavMesh)

**Компоненты:**
- `entranceTrigger` — `Collider` (IsTrigger=true). При входе игрока:
  - `ActivateWalls()` — `wallCollider.enabled = true` для всех стен
  - Босс активируется
- `bossHealth` — ссылка на Health босса. Подписывается на `OnDeath`
- При смерти босса: `DeactivateWalls()` — `wallCollider.enabled = false`

## 8. Архитектурные решения и ограничения

### 8.1 PlayerPrefs как система сохранения
- **Плюсы:** Простота, не требует файловой системы, работает на всех платформах
- **Минусы:**
  - Данные привязаны к устройству (не переносятся между ПК)
  - Хранятся в реестре Windows / plist Mac / XML Android
  - Не шифруются (можно редактировать вручную)
  - Лимит ~1MB на все сохранения
- **Для билда:** Каждый игрок начинает с чистого листа. Для облачных сохранений нужна интеграция (Steam Cloud, PlayFab и т.д.)

### 8.2 DontDestroyOnLoad и root объекты
- `PlayerStats` **должен быть root объектом** сцены (не child другого объекта)
- Иначе `DontDestroyOnLoad` выдаёт предупреждение и может не сработать
- Если объект окажется child'ом после загрузки сцены — `Update()` и другие методы перестанут вызываться

### 8.3 Time.timeScale = 0 и UI
- При `Time.timeScale = 0` обычный `Update()` продолжает работать
- `Time.deltaTime` становится 0, поэтому для анимаций в паузе используем:
  - `Time.unscaledDeltaTime` (CurrencyUI)
  - `WaitForSecondsRealtime` (корутины)
- `EventSystem` нужен для кликов по кнопкам в паузе

### 8.4 LevelUpMenu и CanvasGroup vs SetActive
- Используем `CanvasGroup.alpha = 0` вместо `gameObject.SetActive(false)`
- **Причина:** При `SetActive(false)` компонент LevelUpMenu деактивируется, и `Awake()`/`Start()` вызовутся заново при повторном открытии, что приведёт к дублированию UI
- `CanvasGroup` просто скрывает визуально, но объект остаётся активным

### 8.5 Lazy-connect паттерн
- `HealthUI`, `StaminaUI` используют lazy-connect к целевым компонентам
- **Причина:** Player, Health, Stamina создаются/загружаются динамически, UI может инициализироваться раньше
- Каждый кадр проверяем `if (target == null) target = FindFirstObjectByType<T>()`

## 9. Отладочные горячие клавиши

| Клавиша | Действие | Где обрабатывается |
|---------|----------|-------------------|
| **F9** | Сброс всех статов и душ к дефолту | PlayerController → PlayerStats.ResetAllToDefault() |
| **Escape** | Открыть/закрыть меню паузы | GameManager + GameMenu |
| **E** (у алтаря) | Открыть меню прокачки | LevelUpShrine |
| **Escape** (в меню прокачки) | Закрыть меню прокачки | LevelUpMenu |

**Важно:** F9 работает только в редакторе. Перед финальным билдом рекомендуется удалить/закомментировать обработчик F9 из `PlayerController.Update()`.
